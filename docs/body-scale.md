# 阿福体脂秤

Eir 0.3.0 支持 `AFU-WL-TZ-A1`，协议标识 `afu-wl-tz-a1`。系统可添加多台秤；每块 ESP32-C3 为两台秤和一条血压计连接预留资源，多台血压计继续轮流读取。三设备重叠使用是否通过实机验收，以 `acceptance.md` 为准。

## 添加与成员归属

1. 升级采集端后，确认页面显示体脂秤容量为 2 台。
2. 唤醒秤，在附近采集端执行扫描。在扫描结果中选择设备，核对地址和硬件身份；同名秤通过广播中的 MAC 身份区分。
3. 添加阿福体脂秤，保持其唤醒，等待服务及 FFB2 通知验证完成。
4. 在设备绑定表单选择体脂秤和成员；整台秤对应一位成员，不使用体重猜人。每个成员可拥有多台秤。换绑按采集时间生效，旧记录归属保持不变。
5. 在成员页面填写计算用性别、出生日期、身高。体脂率为估算，页面及导出均明确标记。

秤的测量包没有已经验证的时间或序号，Eir 使用 ESP32 已校时的采集时间。未校时的测量仍保存体重，但时间为空且进入待归属。不能用服务端收到消息的时间冒充实际称重时间。

## 测量与估算

稳定 D5 体重先写入采集端持久队列并上报，同一上秤周期的 D6 ADC 到达后补全同一条记录。两条消息有不同消息 ID、相同 `measurement_session_id`。服务器从原始包独立解析，不信任采集端提供的解析值。

TZ-A1 的 D5 第 6 下标为 `02` 时仍可能是变化中的读数。原始实测通知显示，第 2 下标的高位在屏幕锁定后才置位；解析版本 `afu-tz-a1-v2` 要求两个条件同时满足。不能沿用参考 Swift 仅检查 `raw[6]==2` 的稳定判定。固件 0.3.6 起与服务端均拒绝将这些未锁定通知保存为正式结果。

参考报告中的稳定体重包为 20 字节、D6 示例为 21 字节；参考 Swift 解析器使用固定的第 18 下标。Eir 接受具有已知尾部标识的 20／21 字节包装，按尾部操作码区分 D5／D6，避免把示例 D6 的 `29` 错当操作码。尚未确认校验字节的算法，不声称实现了厂商校验。

每个上秤周期有独立随机 ID。重复锁定通知不增加记录；锁定后重新出现未锁定 D5 即结束旧周期，无需等待零体重包。因此下一次锁定体重即使完全相同也使用新 ID。正常秤端断开结束周期；无线超时在 30 秒重连窗口内保留未完成周期；重连后出现未锁定或不同体重时开始新周期。采集端重启先恢复已保存消息，再建立新采集周期，避免旧周期阻止后续称重。正常休眠、丢链重连仍须用实机确认，协议没有能证明跨连接同一次测量的厂商序号。断电前已经进入持久队列的消息按原 ID 补传。

两路 ADC 原值均保留。默认选 ADC 1，可在每台秤的设置中改选 ADC 2，选择只影响新的记录。归一化与 Segal 估算参照 `Xuan-lprk/smart-body-scale-IOS` 提交 `c11f1b925653b5d14b46eb3b02f6d68551d7e944`，算法版本为 `segal_1988_v1`。年龄按采集日期和上海时区计算，保留计算资料快照及实际 ADC 通道。

选定通道的归一化值不在参考实现的有效范围、没有 ADC 或成员资料不完整时，`body_fat_pct=0`，状态分别表示 `missing_adc`、`missing_profile` 或 `invalid_time`，不使用 BMI 公式兜底。页面显示“—”，体脂率统计排除这些记录。原始 ADC 的物理含义与厂商算法一致性仍未确认。

成员资料变更不重算既有记录；显式纠正测量成员时按所选成员资料重新计算派生指标并记录审计。原始体重和蓝牙包不能修改。第一版不读取 D8 历史，也不向 FFB1 写控制命令。

## 兼容与运维

数据库升级至 schema 3，新增体脂秤数据、成员计算资料、设备硬件身份与 ADC 选择；血压计的用户 1／2 及历史保持原样，体脂秤使用内部用户档位 0。旧客户端未指定测量类型时继续查询血压。

新增设备必须由采集端上报支持的协议及容量，旧固件不能接收体脂秤绑定。体脂秤绑定只验证 GATT 服务和通知，使用空历史基线；清空健康数据时不要求休眠秤醒来读取历史。单设备解绑只清理该秤的本地状态，不能清理其他设备的蓝牙凭据。

源码采用部分参考项目实现，参考项目采用 GPLv3；相关模块标注来源，许可副本位于 `internal/afu/LICENSE.upstream` 和 `firmware/LICENSE.afu`。既有欧姆龙实现及 MIT 声明保留。

软件验证入口：`scripts/body_integration.sh`。它只使用 `eir-test-*` 独立数据库、测试 MQTT 和独立端口；通过结果不等于真实 BLE 三设备并发验收。

采集端本机 `/scale-diagnostics` 默认不采集原始通知。排障时 POST `{"seconds":180}` 可启用最多 180 秒、48 条环形内存缓存，GET 读取；POST `{"seconds":0}` 停止并清空。原始通知只通过采集端局域网 HTTP 返回，不加入 MQTT 状态或持久文件。诊断下载含健康数据，应仅保存在本机私有目录，不能提交版本库。

早期调试中已经保存的未锁定 D5 不删除或修改原文；API 的 `weight_valid=false` 标记它们，页面显示调试提示，CSV 保留有效性字段，所有健康统计和趋势排除这些读数。

## 固定编号

schema 6 为体脂秤新增只读的 `scale_number`。已有秤按创建时间及 ID 顺序补齐，新秤由数据库序列自动分配；界面显示为 `S001`、`S002`。编号不随排序、解绑、其他秤删除而改变，已删除编号不复用。血压计的该字段为空。

编号作为 Eir 的设备元数据保存，MAC／`hardware_id` 继续用于识别硬件，原有设备 ID、采集端分配及成员绑定保持原语义。序列包含在 PostgreSQL 备份中，恢复后继续分配新编号。已有称重原文和估算快照不重算。
