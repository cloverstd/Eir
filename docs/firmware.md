# ESP32-C3 固件

目标为 ESP32-C3、4 MB Flash、分区 ABI `eir-c3-v1`。使用官方 ESP-IDF v6.1，依赖版本固定在 `firmware/dependencies.lock`。协议保留原上游 MIT/GPL 声明。

## 构建

```sh
. /path/to/esp-idf/export.sh
idf.py -C firmware build
python firmware/tools/manifest.py firmware/build/eir_collector.bin
```

应用版本由 `firmware/CMakeLists.txt` 定义；构建清单记录版本、芯片、分区、大小和 SHA-256。OTA 应用必须不超过 0x180000 字节。

## GitHub 产物

PR 和主分支的 Actions artifacts 包含应用、bootloader、分区表、刷机参数、首次刷机 `factory.bin`、校验清单和对应源码。版本标签 `firmware-vX.Y.Z` 必须与工程版本一致，构建通过后在 Releases 发布相同文件。镜像及固件构建不会自动连接真实设备。

- `eir_collector.bin`：已有 Eir 设备的手动 OTA 应用。
- `factory.bin`：首次刷机包，包含分区及初始化区域，只用于已核对身份的目标板。
- `manifest.json`：版本、SHA-256、大小、芯片、分区 ABI、源码提交。
- `SHA256SUMS`：产物校验和；`source.tar.gz`：该提交源码和锁文件。

## 首次配置与升级

首次刷写前核对芯片和 MAC，保留原固件和配置备份；不得将其他用途的板子直接覆盖。已有 Eir 设备优先 OTA，无需擦除 NVS 或更换分区表。

配网页配置 Wi-Fi 和 MQTT 后，在 Eir“设备与采集端”核对发现的设备 ID，再显式添加绑定。支持的血压计和体脂秤按界面配置；未绑定采集端不会开始采集。必要时可用 `firmware/tools/provision.py --port PORT --config PRIVATE_JSON`，私有配置不提交仓库。

手动 OTA：从 Release 下载应用并核对 SHA-256，在 Eir“固件升级”上传 `eir_collector.bin`，核对版本与目标采集端后执行升级。服务端验证芯片、布局、大小、镜像校验和和附加 SHA-256；设备完成启动确认后才视为成功。首次刷机包不能用于 OTA。

## 上传队列并发

固件 0.3.10 修复上传测量时的队列锁与 MQTT API 锁冲突。读取或迁移队列文件时持有存储锁，发布前释放；MQTT 确认回调可以独立删除已确认文件。发布失败时停止本批次，未确认记录继续保留在 Flash，后续重试沿用原消息 ID。每批最多处理 8 个文件，不改变绑定、代次或历史归属。

旧版本可能在仍有待上传记录时停止心跳，MQTT 服务随后显示采集端离线；重启可能暂时恢复。排查时保留 Flash 和待上传记录，核对服务端及设备身份后安装修复固件，不通过清空队列解决。

## 本机蓝牙 / Wi-Fi 摆放测试（0.3.11）

浏览器打开 ESP32 的本机 IP，在首页点击「打开蓝牙 / Wi-Fi 摆放测试」，或直接访问 `/radio`。页面、操作和附近设备数据全部在采集器本机，不要求更新 Eir 服务端；没有新增 MQTT 消息或数据库字段。页面资源内嵌固件，不依赖互联网。

1. 唤醒体脂秤和血压计，退出可能占用它们的手机 App，开始 1、3 或 5 分钟测试。
2. 0.3.13 起，已添加设备在出现时默认关注，并标注血压计／体脂秤类型。手动取消关注在当前页面内保持，自动刷新和重新测试不会强制恢复；重新打开或刷新整个页面后恢复默认。可按名称、MAC 或服务 UUID 筛选，关注目标后可选择只显示关注设备。已分配设备排在其他广播之前。未在 Eir 中添加的设备也可以查看广播；未绑定的采集器可以手动测试，但不会因此启动健康数据采集。
3. 比较 Wi-Fi、蓝牙广播和连接各自的 RSSI、平均值、最弱值、最强值及最近两分钟曲线。关注和曲线保存在当前浏览器页面内存中；刷新页面会重新积累曲线，ESP32 内的本次统计仍保留。
4. 每移动到一个新位置，点击「换位置，重新计数」，丢弃前一位置的诊断统计；停止或到期后保留本次结果。关闭网页不会立即停止设备上的测试，但最迟在选定时长结束。

Wi-Fi 显示 ESP32 到路由器的信号，以及 SSID、接入点 BSSID 和信道；不是手机到 ESP32 配网热点的信号。当前 Wi-Fi RSSI 即使未开始测试也可查看，统计在测试期间约每 2 秒采样，切换 BSSID 时重置。附近 BLE 设备显示广播 MAC／地址类型、名称、广播类型、服务 UUID、厂商编号、可选发射功率和最近的广播／扫描响应十六进制内容。信息来自广播，不主动连接陌生设备或读取其 GATT 信息；未广播的字段显示缺失。随机地址可能变化，厂商编号或名称仅提供线索，不是身份认证。

诊断复用现有 NimBLE 扫描，保持原来的扫描窗口和连接调度。蓝牙广播每个有效包参与统计；已有血压计／体脂秤连接在测试期间约每 2 秒读取一次 RSSI，既有采集或遥测也可能产生额外连接样本。广播和连接分别统计，不能把两个来源的均值直接混用。超过 10 秒无新样本显示旧读数；断开连接显示最近连接读数，不冒充实时连接信号。正在连接设备时扫描可能暂歇，页面显示实际扫描状态。

缓存以 MAC 和地址类型区分，最多 32 项；0.3.12 起，开始测试时为已分配设备预留缓存，连接信号样本也会保护对应项，避免拥挤环境中体脂秤统计不断清零。满时仅替换未受保护且最久未收到信号的附近设备，页面提示发生过替换，重新出现的非目标设备重新计数。休眠的已分配设备仍保留并显示等待信号；若全部 32 项均受保护，暂不接收新地址。诊断仅使用有界 RAM，不写入 NVS／Flash／健康队列；重启清空。网页每 2 秒读取，后台标签页暂停轮询，恢复连接后自动刷新。OTA、生命周期维护或重置准备阶段不允许新测试，并停止正在运行的测试；停止测试不会取消正常采集需要的后台扫描，也不会断开已有连接。

ESP32-C3 这里只扫描 BLE 广播，不包含经典蓝牙；休眠或不广播的设备不会出现。RSSI 只用于同一设备、同一来源的摆放对比，不估算距离，也不保证测量传输成功。选择位置后仍需用真实设备完成一次称重、血压读取和上传对照验收。

本机接口定义见 [`firmware/openapi.json`](../firmware/openapi.json)。浏览器合成验收可使用 `node scripts/radio_ui_test.cjs`（需要可解析的 `playwright` 包和已安装的 Chromium；可用 `EIR_TEST_BROWSER` 指定浏览器可执行文件）。截图默认输出到 `/tmp/eir-radio-ui`，也可通过 `EIR_RADIO_SCREENSHOTS` 指定目录；测试不访问真实采集器或 Eir。

## 诊断内存与任务栈（0.3.14）

体脂秤通知诊断 `/scale-diagnostics` 改为逐条分块返回，最多保留 48 条。读取时不再复制整份环形缓存，也不再预留超过 12 KiB 的连续响应内存；每个输出块小于 512 字节。发送前释放缓存锁，慢客户端或断线不会阻塞测量接收；期间被新通知覆盖的条目跳过，重启诊断不会混入新会话内容。字段保持兼容，原始通知仍只通过本机 HTTP 返回。

主任务栈从 ESP-IDF 默认的 3584 字节提高到 6144 字节，并将队列读取／旧格式迁移函数从主循环分离，避免其 1 KiB 文件缓冲区始终占用信号采样与状态发布的调用栈。队列消息、确认、绑定与分区布局保持原样。`/status` 额外返回 `largest_free_block`（当前最大可用连续堆块）和 `task_stack_min_free`（主任务、已启动 HTTP 任务的历史最小剩余栈，单位字节），供压力验证核对余量。

`reset_reason=4` 只说明异常／panic 后重启，不能独自定位崩溃函数。此前固件未保存崩溃现场，以上更改针对已确认的内存峰值与栈余量风险；没有串口崩溃堆栈时，不将静态分析或短时压力通过等同于唯一根因已经证实。

## 验收边界

CI 编译和镜像格式检查不等同于真实 BLE、配对、断电恢复、OTA 回滚或 24 小时采集验收。真实原始日志、设备地址、健康数据和 Flash 备份由运维私有保存。公开仓库的协议测试均为合成夹具。
